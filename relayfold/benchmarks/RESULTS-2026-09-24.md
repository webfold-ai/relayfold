# Gateway benchmark bring-up — 2026-09-24 AEST

These are **local smoke results**, not incumbent rankings. Raw Nighthawk campaigns are under `results/` (ignored by Git); each `manifest.json` records commands, offered rates, host, and client version. The proxy binary was built from `relayfold` commit `7071305` plus the benchmark adapter and local `biota` commit `e75c90a` with the TCP_NODELAY change described below. Nighthawk's pinned Docker image reported version `0.3.0`. All final HTTP runs used HTTP/1.1, 1 KB response, 20 connections, one event loop, open-loop offer, five seconds, one-second warmup, two repeats.

The final two-path campaign is `results/20260923T144709Z/`. All responses returned HTTP 200 with a 1 KB body in preflight. Earlier runs (`results/20260923T143531Z/` and `results/20260923T144325Z/`) exposed roughly 40 ms of delayed-ACK latency in the Python fixture and another roughly 40 ms in the Biota upstream TCP client. Setting TCP_NODELAY on the fixture's accepted socket and on Biota's upstream socket removed that artifact. The upstream remains a Python `ThreadingHTTPServer` on the same host as client and proxy, and the Biota forwarding path makes an unconditional `eprintln!` per request (`biota/http-server/src/kernel.rs` near `forward_raw`). Those constraints make this a wiring and method check, not a production throughput measurement.

## Seven-path passthrough smoke

The full campaign is `results/20260923T145037Z/`. Every path returned the 1 KB fixture in preflight. At both offers, every target completed 100% of offered requests in both runs, with zero HTTP 4xx/5xx. Values below are the **range across two runs**, not confidence intervals. The tests ran sequentially on one shared host, without CPU pinning or a production upstream; these p99 values do not establish a durable ordering between products.

The single-command launcher was also exercised from free benchmark ports (`results/20260923T145458Z/`): all seven preflights and all seven 100 RPS, two-second runs passed. Its cleanup removed the benchmark containers and child processes. This confirms setup/teardown, not long-run stability.

Tasmanian Cloud's real `edge-lb` binary was attempted with `cargo build -p edge-lb --bin edge-lb --release`. It stopped before linking, in the gateway's own dependency tree, with 34 compile errors, including unresolved `crate::http_helpers` and `crate::sangdb` imports. `cargo build -p biota-http-server --release` succeeded separately, and the small Biota/Relayfold benchmark proxy also built successfully. The `edge-lb` failure must be fixed before claiming its performance.

## MCP protocol smoke

All three gateways used one deterministic backend exposing 100 `echo_NNN` tools. The probe negotiated MCP `2025-06-18`, listed tools, and sent 20 sequential calls that each had to echo a unique value. Results are single-session observations; topology and gateway behavior differ, so the latency columns are **not** a cross-product ranking.

| Gateway and mode | Tools exposed | `tools/list` bytes | Calls passed | Call p50 / p95 ms |
|---|---:|---:|---:|---:|
| Supergateway 4.0.0, stdio → Streamable HTTP | 100 | 15,868 | 20/20 | 6.00 / 11.66 |
| MCP Gateway 3.5.1, search + invoke over Supergateway | 17 | 15,468 | 20/20 | 5.95 / 7.40 |
| MCPJungle 0.4.6, registered Streamable HTTP backend over Supergateway | 100 | 18,446 | 20/20 | 60.23 / 76.05 |

MCP Gateway's compact catalog cut the **definition count**, but its verbose meta-tool definitions made the measured `tools/list` body nearly as large as Supergateway's 100-tool body. A live-agent completed-task comparison is needed before claiming token savings. The gateway's separate search call succeeded in 2.34 ms in this smoke. MCPJungle used an isolated local PostgreSQL container. None of these checks exercised per-tool authorization, streaming, failure recovery, or high concurrency.

The local Ptyktos gateway path is **Conduit federation behind Syndesi**, with Telos as the authorization/decision layer and Agent Loop as the execution layer. It is not represented by the earlier FerrousGate experiment; that name is obsolete and is excluded from this scorecard. Conduit now has passing real-socket HTTP federation tests, but an end-to-end Syndesi + Telos + Agent Loop API-gateway run still needs a deployed listener/configuration that composes those components.
